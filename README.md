## 一、产品定位

**一句话**：说场景和预算，给你一份能直接照着做的花艺配方——不是一张好看的图。

四层价值：**设计 → 决策 → 执行 → 陪伴**。差异化不在"图片好不好看"，而在于方案是否符合预算、花材是否买得到、用户是否做得出来。

## 二、应用结构（6 屏）

| 屏 | 名称 | 职责 |
|---|---|---|
| 1 | 首页 | 品牌、入口、最近方案 |
| 2 | 需求输入 | 场景 / 风格 / 主色 / 预算滑块 / 摆放位置 / 宠物·过敏·含花器开关 |
| 3 | 方案结果 | 配方渲染的效果图 + 花材价 / 含花器价 / 剩余 + 便宜30% / 换配色 |
| 4 | 制作详情 | 花材清单（可点选替换）+ 制作步骤 + 养护建议 + 保存 |
| 5 | 作品 | 上传成品照片 + 规则式自检清单（视觉识别为下一版） |
| 6 | 我的 | 历史方案（localStorage）+ 偏好 |

## 三、核心机制：配方先行、图像受限

本应用最重要的一条设计原则：**先算出合法配方，效果图由配方 SVG 渲染**，因此图片与清单天然一致，不存在"图里有六类花、清单只有四类"的问题。

生成链路（`engine.js`）：
```
需求输入
  → 季节过滤（当月当季花材）
  → 约束排除（宠物有毒 / 花粉过敏 / 场合禁忌）
  → 按风格定配色（色相 ≤ 3）
  → 选品种（主花1–2 / 配花1–2 / 叶材1 / 点缀0–1）
  → 预算分配（主花50% / 配花22% / 叶材15% / 点缀6% / 辅材7%）
  → 枝数换算（主花:配花:叶材 ≈ 1:0.8:1.2；叶材必须多于主花）
  → 超预算裁剪（先砍点缀→配花→主花）
  → 派生：清单 / 价格 / 步骤 / 养护 / 替换 / SVG 效果图
```

## 五、修改能力（点选替换，而非重新生成）

- **便宜 30%**：保持同一设计，按"点睛缀→配花→主花"顺序裁剪数量，命中更低预算。
- **换配色**：轮换风格重算，仍是确定性结果。
- **点选替换**：每种花材旁"换"按钮 → 调出其替代项（同角色、同色系、体量接近）→ 一键替换并重算价格。

## 六、边界与诚实声明

- 价格为一线城市花市参考区间，波动 30–50%，输出标注"以当地为准"。
- 花期、季节为区间/经验值，非承诺。
- **作品页目前为规则式自检清单**，不含视觉识别（识别是同量级第二条 AI 链路，已刻意排除在 MVP 之外，首页"拍下我有的花"为下一版占位）。

## 七、技术栈与运行

- 纯静态单页应用：**HTML + CSS + 原生 JS**，无构建步骤、无外部依赖、无后端。
- 配方引擎为**确定性规则引擎**（同一输入永远得到同一配方），离线可跑，无需 API Key。
- 目录：
  ```
  nocturne-app/
  ├── index.html            入口（6 屏 SPA）
  ├── styles.css            夜花房暗色设计系统
  ├── app.js                控制器（导航/表单/生成/替换/历史）
  ├── engine.js             配方引擎 + SVG 渲染
  ├── data/flowers.js       花材库（40 种）+ 替换表 + 花器
  ├── manifest.webmanifest  PWA 元数据
  └── README.md             本文件
  ```
